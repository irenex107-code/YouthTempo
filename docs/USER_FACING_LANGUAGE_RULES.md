# YouthTempo 用户用语规则

2026年10月28日。适用于中文与英文页面、导航、表单、同意说明、通知、错误、空状态、ARIA和API返回的用户可见提示。本规则作为全站修改基准；本批已据此修订审查所列页面与词条，具体覆盖及仍需真实验证的内容见[本地验收](../deliverables/site-ux-fixes-2026-10-28/README.md)。

## 面向当前使用者

- 首先说明“你可以做什么、会发生什么、接下来怎么做”。用具体动作命名按钮，例如“整理这段感受”“查看支持方式”。避免空泛的“前往处理”“执行操作”。
- 学生页面使用自然、低压力的表达，不以坚持、完成率或情绪好坏评价学生，不把使用顺序写成必须完成的任务链。
- 家长页面说明陪伴与沟通方法；教师页面说明自己负责的学生和可做的支持；学校和平台页面可以使用成员、分配、审核、审计等职责用语。
- 管理员、教师、专业支持者同样是产品用户；他们需要的业务词汇可以保留，但不得把代码、开发说明或实施待办当作操作指引。
- API、RLS、JWT、DTO、fixture、环境变量、表名、内部动作码及异常堆栈不出现在普通用户界面。开发预览与受限诊断页面可保留必要技术说明，并清楚标明用途。

## 名称与层级

- 同一个功能在首页、导航、公开说明、登录后工作台、错误和返回按钮中使用一致名称。内部枚举和数据库值保持稳定，只翻译显示标签。
- 已有功能名称暂沿用；名称改动须同时核对全部入口，不单独给某一页起新名字。SWEET Talk是沟通工具，不是第六个SWEET维度。
- 页面主按钮对应当前主要任务；需要资格的功能区分“了解”“申请”“进入”。已通过审核者不应反复看到首次申请入口。
- 功能未开放时说明当前可用的替代路径，不能将其写成已经提供的服务，也不能通过删除“未开放”提示来营造可用感。

## 说明真实的数据与服务状态

- 谁能看、看什么、什么时候可看必须与实际环境和最新决定一致。不能沿用“学校或老师可看完整SWEET”的笼统旧说明。
- 区分本人记录、自动趋势、学生可选详细分享、私人日记与消息。详细版总开关作用于全部仍保留SWEET历史与新增记录；不暗示只分享开启后的记录或可逐条筛选。
- 本机报告目标与正式环境现状分别说明。当前正式报告和家长私人访问关闭；不得将本机功能写成已经上线。
- 明确匿名针对谁、谁在什么条件下能查来源，不能承诺绝对匿名。说明消息值班和回复限制，不承诺实时在线。
- AI只描述已实现的整理用途及必要处理范围，保持可选，不作诊断、风险评分、因果解释或替人决定。固定规则无需包装为AI。
- 不承诺治愈、疗效、已验证的留存提升、即时专业服务、绝对保密或绝对安全。不把花园参与日数写成心理改善指标。
- “已保存”“已退出”“已撤回”等成功提示必须有确认结果；结果未知时说明尚未确认，并给出核验或重试动作。

## 在操作处说明与选择

- 必要知情说明直接放在相关任务页面；账户保留统一管理入口。简短说明覆盖用途、内容、接收人、可选项、拒绝或撤回的影响及完整说明链接。
- 基础参与确认、可选AI处理、社区/房间规则、详细报告分享及专业职责分别呈现，不能一个勾选默认同意所有用途。
- 使用准确、易懂的“使用前说明”“参与确认”“AI整理说明”“分享详细报告”等标签；正式说明仍可使用“知情同意”，不通过改名弱化其意义。
- 不预先勾选、不把沉默当同意、不暗中扩大范围。只有说明内容、用途或适用版本确实要求时才重新确认，不重复要求完成相同有效确认。
- 确认完成后继续原任务，并保留当前页面尚未提交的内容。确认不等于自动发送、发布或调用AI。
- 年龄、学校入组、关系和专业资格需要可信核验时，明确说明由谁完成；普通用户勾选不能代替核验。

## 错误与恢复

- 错误应包含用户能理解的原因和可执行的下一步。例如“请先完成下方使用说明，再保存这次记录”，不能把缺确认统一写成“稍后再试”。
- 区分未登录、缺少确认、不适用的角色、服务未开放、加载失败、保存结果未知和真实拒绝；不给用户无效重试。
- 服务端只返回安全信息；不把数据库、供应商、约束或任意Error.message直接透传。完整运维诊断只留在受保护的开发流程。
- 无权查看他人内容时不泄露该内容是否存在、真实身份或敏感原因；同时给出适用的返回或支持入口。
- 无记录、记录未加载和无法解读是不同状态。“没有数据显示”不能解释为没有需要支持的情况。

## 语言、透明度与可读性

- 中文为源语言，英文含义、开放状态和限制一致；英文使用专业、温和、直接的表达。SWEET model保持统一。
- 用户可见的中文/英文标签、占位、辅助文本和ARIA均进入双语词典；禁止中文页面遗留硬编码英文栏目标题。
- 日期按界面语言显示，不翻译用户原文和内部状态值；对外展示的状态使用受控标签映射及安全的未知状态兜底。
- 安全和非诊断边界放在对用户有实际意义的位置，避免每张卡片堆叠重复否定句；不能删掉对当前操作必要的限制。
- 处理用途、AI使用、必要保留时间、接收范围和版本可以依法如实说明；“去内部用语”不能变成隐瞒数据处理事实。
- 长说明分为短摘要和可展开详情；不得将关键用途、分享范围和拒绝后果只藏在远处隐私页。

## 发布前核对

每次修改核对：当前角色能否理解并执行；名称与其他入口是否一致；按钮是否到正确目标；隐私与服务状态是否准确；错误能否恢复；中英文是否一致；键盘、读屏、手机尺寸是否可用。未完成实际角色操作和截图核验，不标记全站用语或流程已通过。
