# 青少年 AI Talk 首轮试点关闭决定

## 决定

- 决定日期：2026-08-18
- 关闭版本：`talk-closed-2026-08-18`
- 范围：青少年端“陪我捋一捋”（路由 `/talk`、接口 `/api/ai/talk`）在首轮学校试点期间关闭。
- 不在范围内：家长端基于 AIDET 的 SWEET Talk 沟通指引。SWEET Talk 不是 AI 对话，也不是 SWEET 第六维。

## 产品与技术行为

1. `/talk` 只显示暂停说明和替代支持入口，不提供输入框、对话记录或 AI 告知勾选，也不向服务端发送对话内容。
2. 普通 `POST /api/ai/talk` 请求返回 HTTP 410、`closed: true` 和关闭版本，不调用 AI provider。
3. 为兼容旧客户端，接口仍在普通关闭回应之前检查本次会话的全部用户消息。明确自伤、自杀、无法保证安全或正在被伤害的信号，只返回固定的现实支持指引，不调用 AI provider。
4. 替代入口为：规则化的“下一步找谁”、悄悄话信箱、心情拼图，以及现实中的家长、老师、学校支持人员或当地紧急服务。

## 关闭理由

开放式陪伴对话容易让青少年误解 AI 的身份和能力，并可能形成对“持续理解、专业判断或即时照护”的不合理期待。首轮学校试点尚未完成这一交互的专业适用性证明、会话边界审核、升级责任和学校线下承接签字，因此不把它作为试点功能。

## 重新开放的必要条件

重新开放不是默认后续步骤。任何提案须先完成并留存以下证据：

- 心理专业负责人审核具体使用目的、适用年龄、禁用场景、语言和误导风险；
- 学校明确值班时段、升级联系人、响应责任和平台不可用时的线下路径；
- 将开放式连续对话改为可验证的结构化任务，限定轮次、输入范围和结束条件；
- 对危机漏报、误报、提示注入、依赖性表达、拟人化、越界建议和双语差异进行专项测试；
- 完成 provider、保留期限、训练使用、处理地点、跨境、访问控制和删除流程的法务及隐私核对；
- 提供青少年可理解的版本化告知，并确认 AI 身份在整个交互中持续可见；
- 经产品、心理专业、安全/隐私及学校负责人书面批准，并在新的关闭/开放版本记录中更新路线图。

## 当前剩余条件

关闭 Talk 降低了首轮试点范围，但不关闭 YouthTempo 的整体 AI P0 治理阻塞项。Worry Time 已于 2026-08-18 改为固定规则；现有 Check-in、Mood Journal 与小程序 Check-in 的 AI 摘要仍需完成法务、隐私、专业及学校签字；所有支持入口的固定危机文案和现实承接流程也仍需联合审核。
