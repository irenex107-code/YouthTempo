# YouthTempo 运行错误监控

更新时间：2026-08-03

## 已覆盖范围

- 登录：会话读取、登录回跳、邮箱验证码发送与验证。
- 保存：SWEET 云端保存。
- AI：SWEET、心情拼图、陪我捋一捋、今晚先放下、下一步找谁，以及 AI 限流服务。
- 社区：帖子、评论与发布限流服务。

服务端错误以单行 JSON 输出到标准错误流，CloudBase Run 运行日志可直接检索 `"event":"operation_failed"`。浏览器端只向 `/api/monitoring/client-error` 提交固定操作码和错误类别；接口限制为 2 KB，并对单一来源做每分钟 30 次的进程内保护。

## 隐私边界

监控事件只包含时间、业务区域、固定操作名、错误类别、HTTP 状态、请求 ID，以及经过字符白名单过滤的错误名称和错误码。不得记录或转发：

- 邮箱、验证码、Access Token、数据库连接串或任何密钥；
- SWEET 原始回答、AI 输入与输出；
- 社区帖子、评论、举报详情；
- 用户 ID、IP 原文、错误消息或堆栈。

客户端来源只在内存中以 SHA-256 摘要用于短时限流，不写入日志或数据库。

## 告警接入

未配置外部接收端时，结构化事件仍会进入 CloudBase Run 日志。配置以下服务端环境变量后，同一份脱敏事件会同步发送到 HTTPS 告警接收端：

```text
ERROR_MONITOR_WEBHOOK_URL
ERROR_MONITOR_WEBHOOK_TOKEN
```

接收端应在 2 秒内返回 2xx。超时、网络失败或非 2xx 会额外产生 `monitor_delivery_failed` 日志，但不会影响原业务响应。

正式告警建议至少建立：

- 5 分钟内任一 `area` 出现 3 次 `operation_failed`：提醒负责人检查；
- 5 分钟内出现 10 次，或 `monitor_delivery_failed` 连续出现：升级为紧急告警；
- 按 `area` 区分登录、保存、AI、社区，告警内容不附带原始请求或用户数据。

## 验收标准

1. 向监控接口提交合法固定事件得到 `202`，非法字段得到 `400`，其他方法得到 `405`。
2. CloudBase Run 日志能检索到对应结构化事件，且不包含测试邮箱、验证码或正文样本。
3. 告警接收端能收到脱敏事件；断开接收端时业务仍正常响应，并出现 `monitor_delivery_failed`。
4. 对登录、保存、AI、社区各触发一次受控失败，确认四类事件均可检索和告警。
