# 全历史 SWEET 综合报告：本地实施与数据库范围

日期：2026-10-28。状态：**产品设计及本文本地范围已获负责人明确确认；本地实现和隔离验收已完成，正式功能未开放。** 项目仍为 **READY WITH CONDITIONS**。

产品依据：[已确认的两层分享设计](../../../deliverables/report-sharing-policy-2026-10-28/two-level-design.md)。本文替代旧的可选趋势用途两表草案，不替代学校、隐私或运营签署。

## 1. 这次要交付的行为

- 完成可信学校入组、处理依据有效且关系有效后，当前负责老师自动看到同一份持续更新的趋势报告；不再要求学生选择老师、维度或点击开启趋势。
- 报告包含全历史概览、长程时间分布、最近7天/30天以及紧邻前期比较，使用同一个截至时点。每次读取均据仍保留的来源重算。
- 学生只有一个默认关闭的“分享详细 SWEET 报告”开关。开启后向当前获准接收集合开放全部仍保存的 SWEET 答案、日期、补充文字及单次小结，也包括开启前、关闭期间和以后新增的记录；不逐条挑选。
- 关闭详细版仍提供有效趋势。接收集合变化后详细版复位关闭；恢复关系、旧请求重试和重新入组均不能复活旧详细访问。
- 本批数据库和应用接收集合均只接入老师。已核验监护人属于目标接收类型，但当前家长工作流全局关闭及禁止新增 active 关系的约束保持原样；新版本家长请求验证拒绝，正向工作流另批，不声称已开放家长报告。
- 只在本机一次性 Supabase、合成账户和非 production 的显式本地门禁内实施、验收。production 即使配置开关 true 仍拒绝。

## 3. 可信入组、期限及退出

入组不是客户端布尔值，也不由“已有学校/监护关系”自动生成。服务端内部流程核验当前学校、学生角色、学校成员关系、有效基础确认、最新可信14–17岁资格和明确的报告用途材料引用。已有学校管理员或平台管理员可在其职责范围内作为核验操作者；他们因此不会获得报告正文读取权。适用的本人/监护确认可由学校核验线下材料并登记新用途的受限凭证引用；不伪造平台监护账号、active链接或旧确认时间。只有现行基础确认也不能通过入组。

新入组记录明确保存：用途/告知版本、`all_retained_history` 范围、经审阅的处理依据材料引用、告知完成材料引用、可信签发者、生效和到期时间、学校及未成年资格引用。引用仅使用受限的不透明编号，不保存身份证件、正文或“自由填写的法律理由”。编号本身不证明签署真实存在；正式流程必须由指定责任人核对，本批只用明确标为 synthetic 的材料。

版本分别为 `school-reports-2026-10-28`（入组用途）、`sweet-details-2026-10-28`（详细告知）、`sweet-comprehensive-report-v2`（趋势输出）和 `sweet-history-details-v1`（详情输出）。它们都不加入基础、AI、社区或消息的全局同意白名单。

学校登记结束时间不是现有 `schools` 字段：本批在新入组记录不可变保存 `school_registered_until` 和 `basis_valid_until`，由可信签发流程根据学校登记及用途材料核验并提供，普通客户端无签发入口。每次入组访问到期取签发时刻加30×24小时、可信未成年截止、这两个材料期限中的最早值；缺失/非有限/已到期拒绝。材料提前撤回或更换由可信流程立即调用终止事务，不假称数据库能自动感知线下材料变化。

到期即拒绝读取，不等后台任务。续期只能由可信流程重新核对并签发新入组 ID；不修改旧到期时间、不自动循环续期、不复活旧对象。新入组详细版从关闭开始，学生需要时一键重新开启。学生不需要操作趋势开关。

基础确认撤回、资格撤销或更换、学校停用、离校、学生角色/所属学校改变、退出该报告入组，均终止入组和详细状态。当前接收关系撤销仅使对应接收人失权，并更新整个当前接收集合、复位详细开关；其余合法老师的趋势继续有效。恢复已终止的事实不恢复旧入组。

学生有学校入组状态和退出/联系学校处理路径；详细开关不会被误用为退出入组。学校入组终止不删除本人 SWEET，也不因此关闭本人基础记录功能。自主试用、未满14岁、成年人分享均不自动转为学校共享。

## 4. 已批准的数据库变更清单

使用 Supabase CLI 新建一项迁移，随后同步 `supabase/schema.sql`；不重写已存在的迁移文件。新增四表：

| 表 | 最少内容与约束 |
| --- | --- |
| `school_report_enrollments` | 学生/学校/最新未成年资格引用、用途/告知/全历史范围和核验材料编号、签发者、`school_registered_until`、`basis_valid_until`、生效/有限到期、active/withdrawn/invalidated 状态及真实 `terminal_at`、请求ID；当前 `recipient_epoch`、接收集合指纹及 `source_revision`。每名学生同一用途最多一条活动入组；创建新入组先终止旧条目。 |
| `school_report_detail_states` | 每条入组唯一的详细状态；默认 OFF、`detail_revision`、明确开启者/时间/告知版本、开启绑定的 `recipient_epoch`。只能学生本人通过事务开启；不能直接更新成另一人的确认。 |
| `school_report_sharing_events` | 入组签发/续期/退出/失效、接收集合变化和学生开关的最少事件；对象、操作者、固定事件类型、版本、时间、请求ID及命令的受限状态。用于幂等回执，禁止正文、邮箱、材料原文、token或任意请求 JSON。 |
| `school_report_mode_access_audit` | 入组、操作者、trend/detail 模式、版本、允许/拒绝/资料不足/来源变化等固定结果和时间；不存报告正文、单条日期列表、次数、游标或IP。 |

四表全部启用 RLS；`PUBLIC`、`anon`、`authenticated` 无表权限和函数执行权。服务角色仅获业务所需的 select/insert/update，以及执行受限清理所需的四表 delete；不使用 GRANT ALL，不把清理参数开放给浏览器。事件及审计业务上只追加，外键匿名化、账户注销和超期清理是明确的维护例外。账户注销、学校删除的外键行为逐表明确，兼容 GoTrue 删除，不新增对 Auth 内表的宽泛写权限。

外键与维护规则固定如下：入组的学生/学校引用 `ON DELETE CASCADE`，资格与签发者引用 `ON DELETE SET NULL`；资格删除先终止相关活动入组，再置空引用，不能留下无资格的活动状态。详细状态的入组引用 `CASCADE`、本人开启者引用 `SET NULL`。事件/审计的入组及操作者引用 `SET NULL`。入组删除前，有限内部维护触发器清除对应事件/审计的入组ID、操作者、请求ID及可关联指纹，仅保留固定事件/结果、用途版本和时间；再执行级联，不把其他学生对象删除。服务角色 UPDATE 仅授予入组/详细状态；事件/审计只给 SELECT/INSERT，匿名化通过上述受限维护完成。

服务角色专用、固定空 `search_path`、`SECURITY INVOKER` 的业务事务：

1. `issue_school_report_enrollment`：可信签发/续期；校验操作者当前职责、学校、基础确认和最新资格，绑定固定用途/范围与有限期限。无面向普通浏览器的“已核验/已签署”参数入口。
2. `end_school_report_enrollment`：本人退出或可信管理终止；事务内关闭详情、递增版本、记事件。接收人不能用它替学生关闭趋势。
3. `read_school_report_access`：本人管理状态/当前接收人，或接收方最少的当前有效学生入口；不返回原始同意材料、核验编号或邮箱，列表必须分页，不能只取前30条并当作完整集合。
4. `set_school_report_details`：学生本人开关，固定全历史/全部当前接收集合，无维度/记录筛选参数，幂等及乱序规则见第7节。
5. `read_school_report_trend`：验证当前访问后在数据库内扫描完整来源并聚合，只返回受限 v2 DTO；查询不能依赖 PostgREST 默认行数上限。
6. `read_school_report_details`：验证当前详细状态、接收资格和版本后返回受限分页；拒绝时不返回部分正文。
7. `validate_school_report_view`：返回前复核访问、来源和开关版本，不返回正文，用于丢弃失效或已变化的结果。
8. `purge_expired_school_report_metadata`：服务内部最少清理函数，只处理已终止且超过下述保留期的元数据；本批仅用隔离合成数据验证，不创建远程任务或清理真实数据。

修订现有 `issue_report_minor_eligibility` 的基础门禁，使其要求现行有效 `2026-08-28` 基础确认；允许现行的 `student_self_pilot` / `student_guardian` 基础状态，不再要求报告专用旧版本或为年龄核验伪造监护字段。可信年龄核验、当前角色/学校及最新资格不可回退规则保留。该签发本身不创建学校入组；新报告用途及适用监护材料须由独立入组流程核验。保留 profile 角色保护、本人保存触发器和其同意边界。

依赖写锁覆盖新表；使用现有同一固定 advisory transaction mutex 和 READ COMMITTED 顺序。新增/收紧内部触发器：保护不可变范围/事件、依赖失效、接收集合变化复位、SWEET insert/update/delete 递增相关 `source_revision`。内部失效维护确需有限 `SECURITY DEFINER` 时沿用现有纯触发器模式：无公共执行权、空搜索路径、固定表与旧行谓词，不能借此开放业务读取。

不向普通老师/家长恢复 `sweet_records` SELECT，不增加公开视图、原始 JSON RPC或服务端全文兜底。`report_authorizations` 四张旧基础表保留，不为新模式扩展成另一套接收人授权；旧业务入口的撤销、旧活动对象的终止及新表依赖是本次全部旧报告 SQL 变更范围。

新元数据不复制 SWEET 正文。活动入组及其必要状态随业务有效；入组终止后最多保留24个月，随后连同对应开关/事件/审计由上述受限函数清理。终止锚点为实际 `terminal_at` 与自然 `expires_at` 中较早者；字段仍为 active 但已自然到期的对象，也按原 `expires_at` 计算，不能在清理时把锚点重置成现在而无限延后。独立拒绝审计及已匿名化事件最多自创建起保留24个月，活动未到期数据不能被清理。账户注销删除入组和详细状态，事件/审计只可保留上述已去关联的最少运维结果；不可把新的24个月技术上限当成法定评估材料的保存规则。正式保留依据与自动清理作业仍须在真实开放前审阅。

## 5. 完整历史来源及趋势算法

### 5.1 来源和截至时点

数据库取得本次截至时点 `asOf`，所有分析窗口及详情页共用；来源时刻满足 `created_at < asOf`。按学生本人 `user_id` 取仍保留的 SWEET，**不按当前学校、入组日、关系开始日或开关日过滤**；包括此前 `school_id=null` 和旧学校保存的本人记录。当前学校/关系决定谁可读，不能偷换成来源时间/学校限制。前校来源的处理须被本次全历史用途覆盖；未解决的特定目的限制必须阻止入组并说明，不能静默漏行后称全历史。

记录时间保留 PostgreSQL 微秒，日归属使用上海时区。先取 `asOf` 之前每个上海日期仍保留的最后一条记录，建立趋势、详情和所有窗口共用的“每日当前记录”集合，再筛选各分析窗口。最新时刻多行内容一致则合并：一致性只比较规范化的已知字段/格式状态与原 `summary`，排除行ID、学校、存储的标题/label及范围外键。内容冲突则该日标记冲突，不按UUID任选正文。最新记录未知/格式不完整时不能回退当天较早内容，避免把已更正的旧答案重新公开。详情不从备份、已删除或已被替换数据恢复内容。

非有限时间（包括PostgreSQL Infinity）不能进入区间或分箱，标记覆盖受限。详细版最后单独分页列出无有效日期的 `unsupported` 占位：日期为null、仅不透明标识/状态，无原答案或小结；以稳定不透明排序键遍历，不伪造日期。有限的未来来源时刻不在本次截至范围，稍后达到时点才纳入。SQL和TypeScript均测试这些边界。

五维分别按当前主选项的精确固定值验证：每维每天至多一个依据，未知/缺失不计该维，不当作零值，也不连带剔除其他已识别维度。不猜测未知结构，不把英文显示文案当存储值。旧的“先过滤有效整份、再找最后记录”适配器保留为v1历史，不能直接复用作新来源层。

趋势另有 `coverage: complete | partial | unsupported`，表达存在不能解读的来源，不返回数量。覆盖起点/截至日期为区间说明，不返回逐条日期。全无有效资料显示资料不足，不能写“正常/没有变化”。

### 5.2 同一报告中的时间视角

| 部分 | 明确定义 |
| --- | --- |
| 全历史概览 | 最早仍保留记录至 `asOf`；五维按不同上海日期等权计算类别概括，仅称“最常出现的选项”，不称长期变化。 |
| 最近7天及前期 | 当前 `[asOf-7×24h, asOf)`；前期 `[asOf-14×24h, asOf-7×24h)`。 |
| 最近30天及前期 | 当前 `[asOf-30×24h, asOf)`；前期 `[asOf-60×24h, asOf-30×24h)`。 |
| 长程变化 | 从最早有效日期至 `asOf` 所在上海日期按包含首尾的日历天数计算跨度（同日为1天）；不超过90天使用上海周一零点起的自然周箱，超过90天用上海自然月箱。无有效日期则无箱并显示不足。首箱起点早于实际覆盖起点、尾箱终点晚于asOf时标记未完整覆盖；空箱也返回不足，箱之间不插补资料，不把缺失期连接为连续轨迹。 |

共同每日记录按最终来源时刻归入对应窗口，同一天在相邻两个窗口至多进入其中一个；界面说明这是滚动时窗，不称完整自然日比较。每窗口/箱、每维至少3个不同有效上海日期才给类别；并列最高显示“分散”；唯一最高返回类别枚举。没有有效类别且存在未知/冲突来源时为unsupported；空窗口或有1–2日有效依据时为insufficient。前后均有唯一类别时仅给 `same` / `different`；其他情况 `unavailable`。运动“不太确定”作为已知回答展示，但不据此判断活动变化。

长程图单独显示各箱及缺失/不足状态，防止近期密集记录掩盖过去。长程箱也分页，每页最多24箱，能向前遍历全部历史，不截成“最近24个月”；数据库先完成全历史聚合，传输分页不改变概览/近期结果。

趋势 DTO 只含版本、`asOf`、覆盖区间/完整性枚举、固定五维类别/分散/不足和比较枚举、时间箱边界及受限分页标记。不直接返回可当作参与计数的内部 `source_revision`；分页标记为不透明密文。无样本数、比例、每日列表、原文、单次小结、身份材料、AI诊断/风险等级。身份入口与报告内容契约分开，显示名只来自当前授权关系，绝不以邮箱兜底。不新增 AI 调用。

纯 TypeScript 实现同一算法作为合成预览和 SQL 对照，实际成人接口只读取数据库聚合结果；不能把完整来源拉到浏览器计算趋势。

## 6. 详细白名单和分页

每条详细 DTO 仅包含不透明记录标识、原记录日期、以下字段的值，以及 `sweet_records.summary` 单次小结文本。标题/选项显示采用现有双语字典，用户补充文字和原小结不翻译，不执行 HTML。

| 维度 | 允许的字段 ID |
| --- | --- |
| sleep | quality、duration、factors、note |
| wake | state、factors、note |
| eat | rhythm、mealCount、foodDetails、factors |
| exercise | duration、activityTypes、activityNote、bodyState、factors |
| task | engagement、difficultyReasons、completedSmallTask |

固定选项按当前保存契约验证，已知补充文字只作字符串；不返回来源 `title`、`label` 或未知键。重复字段、未知结构或超出安全传输边界的条目标记格式/展示受限，不能私自猜字段、默默截断后声称完整。`summary=null` 明示没有已保存小结，不调用AI补写。

不返回 `small_step`、`recommended_next_tool`、SWEET之外的记录或数据库整行。`task.completedSmallTask` 是学生填写的 SWEET 答案；它与被排除的 AI `small_step` 是两个不同来源。

历史明细按上海日期倒序 keyset 分页，每页最多25个日期的当前记录或格式/冲突占位；同日已被替代的旧行不作为另一条历史公开。分页仅控制浏览，不是分享筛选。游标绑定查看人、学生、入组 ID、截至时点、来源版本、接收集合版本、详细版本和最后日期排序键；它不授予访问，每页仍独立核验当前会话和所有权限。使用服务端认证加密及最长5分钟有效期，不向成人发送可解码的版本计数/他人集合。仅本机运行可用进程内随机密钥，重启即要求刷新，不新增正式环境密钥或远程配置。任一版本改变则丢弃旧页、清空已加载详情并重新取得报告，不能拼接两个来源版本。

游标内部还绑定模式和 `phase=dated|undated`，无日期阶段按来源UUID稳定排序，但只以密文传输。长程箱游标绑定相同来源/访问上下文及最后箱边界；不能拿趋势游标读取详情。首包返回加密 `viewToken` 供详情首读及状态复核，以便沿用同一 `asOf`；它同样不是访问凭证。

完整性测试逐页遍历并与数据库当前应有的最终记录集合比较，覆盖超过默认1000行的历史，不能只检查第一页。不持久化报告快照/正文，不生成导出链接，不把游标、正文放入 localStorage/sessionStorage、日志或监控。

## 7. 总开关、并发和失败恢复

- 开启命令须带请求 UUID、本人当前看到的 `detail_revision` 和 `recipient_epoch`、固定告知版本及明确确认；服务端从会话确定本人，事务内重查当前完整、非空的接收集合。过时版本拒绝开启。本人可依自身数据权在关闭状态预览详细范围，预览绑定本人身份，不能被接收人复用，也不改变分享状态。
- 关闭命令针对当前入组，允许本人安全地停止尚未确认结果的开启；每次新的关闭命令即使原来已 OFF 也递增详细版本，使排队或超时的旧 ON 不能随后重新打开。旧入组关闭不能作用到新入组。
- 同一个请求 UUID 只能对应同一命令。重试只返回已记录回执及当前权威状态，不重新执行旧 ON/OFF；同一 UUID 换参数拒绝。界面必须以重新读取的当前状态确认结果，不以历史回执代替。
- 新增/减少接收人、分配或监护关系的身份/有效性变化，更新接收集合版本并将详细版复位 OFF。集合从A改B再回A也已是新版本；旧开启、旧游标不能复活。
- SWEET 保存、更正、删除改变来源版本；趋势及详情返回前复核。来源变化返回可安全重试的 `refresh_required`，不发送部分正文或把不完整查询当作成功。
- 读取与关闭/失效按同一事务锁确定先后：关闭先完成的读取必须拒绝详情；已在关闭之前获准的内容不能承诺远程收回。前端一旦获知关闭、版本改变或失权，即清空详情并拒绝迟到结果重新渲染。
- 接收方保持页面内存数据，定期只检查最少访问状态，切回窗口/可见、到期及每次翻页都复核；隐藏、退出、换号、403/404立即清空并取消请求。状态轮询不复制正文，也不能被描述成另一设备的即时远程擦除。
- 请求中/结果未知明确展示等待或恢复状态，不宣称操作成功。关闭按钮先清空本浏览器详情，再确认服务端结果；刷新重试保留同一命令ID直到查清。

不增加 Realtime 推送、邮件、短信、外部告警或持久缓存。任何错误只返回双语用户安全文案和固定业务状态，不回传数据库/provider异常。

## 8. 页面及 API 改造范围

保留 Pages Router 和现有本机门禁、bearer 验证、Origin/参数白名单、4KB/5秒输入边界、no-store及15秒客户端超时。新增必要读契约与开关，不接受 actor、role、school、已核验或任意维度/记录列表作为客户端授权输入。

路由及参数固定为：`GET /api/reports/access?locale=` 返回最少当前状态及入口首包，后续入口页用同路径POST `{locale,cursor}`；`GET /api/reports/current?enrollmentId=&locale=` 返回综合趋势首包；`POST /api/reports/history` 接收 `{enrollmentId,locale,cursor}` 返回后续长程箱页；`POST /api/reports/details` 接收 `{enrollmentId,locale,viewToken,cursor?}` 返回详情页；`POST /api/reports/details-setting` 接收本人开关命令；`POST /api/reports/validate` 接收 `{enrollmentId,locale,viewToken}`；`POST /api/reports/enrollment-exit` 接收 `{enrollmentId,locale,requestId,confirmed:true}`。所有游标/viewToken只放请求体，避免进入URL日志；它们不含可见内部版本。开启命令为 `{enrollmentId,locale,requestId,enabled:true,expectedDetailRevision,expectedRecipientEpoch,policyVersion,confirmed:true}`，关闭命令为 `{enrollmentId,locale,requestId,enabled:false}`；多余字段拒绝。

趋势成功契约为 `{version,asOf,viewToken,coverage,overview,recent:{days7,days30},longTerm:{unit,bins,nextCursor},detailsState}`。days7/days30均为 `{current,previous,comparisons}`，comparisons按五维返回 `{id,state}`，state仅same/different/unavailable。每次长程翻页返回同一asOf及相同overview/recent，只有bins/nextCursor变化；版本变更要求整份刷新。窗口/箱的维度固定为 `{id,state,category?}`，state为category/mixed/insufficient/unsupported；比较为固定same/different/unavailable，不能在无类别时夹带旧值。`coverage`只含有限起止范围与complete/partial/unsupported状态，不含计数。详情成功契约为 `{version,asOf,viewToken,items,nextCursor}`，items为第6节白名单或格式占位，不混进趋势DTO。

安全错误为 `{error:双语文案,code:固定枚举}`：400 `invalid_request`、401 `sign_in_required`、403 `access_denied`、404 `unavailable`（含生产门禁）、409 `refresh_required`（来源/游标变化）或 `stale_setting`（旧开启版本）、503 `temporarily_unavailable`。到期/失权均403并清空，不返回部分报告；稀疏/未知是200内的数据状态，不伪装接口错误。任何新错误码保持中英文意义一致，不用原始数据库错误作code。

可信签发/续期只由本机验收内部脚本调用，不新增生产管理入口。旧 `/api/reports/authorizations` 及其逐项删除接口返回安全拒绝，不继续代理旧 RPC。

`/reports` 展示学校入组状态、当前负责老师、全历史范围和有效期、同一报告的时间区间。学生看到一个详细开关及实际接收集合预览；接收方默认只显示趋势，详情有效才出现历史区块。去掉逐维度/逐接收人授权和“停止趋势”操作。家长关闭状态明确显示，不创建邀请、关系或替学生开启。

只修改报告模块、必要的详情字段元数据提取、报告 API、报告词典键、报告测试/隔离脚本及状态文件；不借机重构账户、AI、garden或公开页面。新的语义翻译键同时加入中英文，保留原值与布局体系。`/reports-preview` 若继续展示旧模型需标注历史预览；本批合成预览改用新综合报告契约，不让旧预览冒充当前产品。
