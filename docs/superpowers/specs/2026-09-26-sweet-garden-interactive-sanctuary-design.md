# SWEET 花园互动庭院设计

日期：2026-09-26
状态：书面设计已确认，等待实施计划复核；尚未授权实现或数据库变更

## 1. 背景

现有 SWEET 花园已经提供首次介绍、四阶段植物、参与统计、轻量记录、完整 SWEET 入口和提醒设置。它能说明“参与会带来成长”，但主要体验仍是一张阶段插画加表单，用户难以感到自己拥有一座可以反复进入、照料和探索的花园。

第二阶段把花园改造成一个长期存在的个人疗愈庭院。视觉基准不是网站其他宣传插画，也不是后续尝试的几何场景，而是本轮最早确认的 C 方向小草稿：开阔浅色天空、柔和草坡、池塘、长椅、一株主植物和少量访客组成的安静庭院。

## 2. 目标

- 用户进入页面后先看到完整庭院，而不是先看到表单。
- 轻量记录或完整 SWEET 参与后，用户可以选择一次轻照料并立即看到反馈。
- 用户即使当天不记录，也能自由点击庭院中的少量位置进行轻探索。
- 庭院随参与日逐步丰富，并允许用户在固定位置选择预制物件。
- 用户可以主动把某个参与日保存为无自由文本的纪念物。
- 体验保持私密、双语、移动可用、减少动态效果可用，不排名、不惩罚漏记、不把感受好坏转成奖励差异。
- 花园区域完全不出现、读取、调用或生成 AI 内容。

## 3. 非目标

- 不增加第六个 SWEET 维度。
- 不加入金币、能量、排行榜、连续签到奖励、断签惩罚、植物枯萎或付费物件。
- 不建立自由拖放、缩放、旋转的装修编辑器。
- 不加入虚拟人物、聊天角色或 AI 陪伴者。
- 不把 SWEET 回答、AI 小结、自由文本或风险判断复制进花园数据。
- 不向家长、老师、学校工作台、平台管理页面或公开页面提供庭院内容。
- 不在运行时生成插画、装饰物或纪念文案。

## 4. 体验原则

### 4.1 参与，而非表现

成长只取决于用户是否在一个上海日历日内完成过轻量记录或完整 SWEET。感受选项、答案内容和 AI 输出均不影响成长、动画、解锁或物件质量。

### 4.2 不制造补偿压力

同一天多次记录只贡献一个参与日。漏记不会减少参与日、撤销物件或让植物倒退。页面不显示连续签到数字，也不提示“补签”。

### 4.3 庭院本身有价值

用户无需先完成任务才能进入庭院。池塘、长椅、植物和访客始终可探索；记录只解锁当天一次照料和长期成长。

### 4.4 用户选择有限但有意义

正式版本采用固定位置布置。系统保证构图协调，用户选择在已解锁位置放置哪个预制物件。第一版不提供任意拖放。

## 5. 核心互动循环

1. 用户进入庭院，先看到当前场景和当天状态。
2. 当天尚无参与记录时，页面以克制文案提供“记录一下”和“完整 SWEET”入口；用户也可以忽略提示，直接探索。
3. 用户完成轻量记录或完整 SWEET 后，当天获得一次照料机会。
4. 用户选择浇水、日照或邀请访客。三个选择获得相同成长，只播放不同的短动画。
5. 服务端确认照料成功后，客户端播放反馈并刷新庭院状态。
6. 达到成长节点时，用户从当前位置允许的预制物件中选择一个进行布置。
7. 用户可以选择把当天保存为花、石头或小灯等纪念物。纪念物只记录日期和类型，不自动赋予情绪含义。

## 6. 成长规则

### 6.1 参与日计算

服务端把 `tempo_check_ins` 和 `sweet_records` 的 `created_at` 转成上海日期，合并后按日期去重。返回的本周、本月和累计数字都以去重后的参与日为准。现有按原始记录条数计算的花园汇总将调整为按参与日计算。

### 6.2 可见节点

| 参与日 | 可见变化 |
| --- | --- |
| 0 | 保留种子与基础庭院，不显示失败或荒废状态 |
| 1 | 主植物发芽 |
| 3 | 主植物长叶，开放第一个固定布置位 |
| 7 | 主植物开花，出现第一位动物访客 |
| 14 | 完成池塘或长椅角落，并开放新的物件选择 |
| 28 | 庭院达到完整成熟状态，后续参与只增加轮换访客和可选物件，不再提高压力等级 |

现有 `seed`、`sprout`、`leaves`、`bloom` 继续描述主植物，避免破坏既有响应合同；新增独立的庭院场景等级描述 14 日和 28 日后的整体丰富程度。

## 7. 视觉系统

### 7.1 构图基准

正式插画延续最初小草稿的空间关系：上方为开阔天空，中景为柔和草坡，前景放置池塘、长椅和主植物，少量访客出现在中远景。页面不改造成仪表盘、品牌宣传图或重度游戏地图。

### 7.2 正式资产

第一版需要一套统一制作的预制资产：

- 一张可分层的庭院主场景，包含桌面与手机安全裁切区。
- 主植物的种子、发芽、长叶和开花四个状态。
- 浇水、日照、访客三组短动画及对应静态完成状态。
- 池塘水波、叶片轻动和访客停留的探索反馈。
- 四个固定布置位和八个首发装饰物。
- 花、石头、小灯三类纪念物。
- 记录、照料、布置、关闭、返回等同一笔触的功能图标。

所有资产使用统一的轮廓、比例、材质、低饱和色板和阴影逻辑。不得以平台 emoji 代替场景物件或功能图标，不使用发光星星、粒子爆炸或游戏货币特效。

### 7.3 动效

动效以 200–600 毫秒的局部反馈为主，不持续吸引注意。减少动态效果开启时，所有动画替换为静态前后状态和文字状态提示。环境声默认关闭；第一版不主动播放音频。

## 8. 页面与组件结构

`/garden` 继续使用 Pages Router 入口。页面实现拆为以下职责清晰的组件：

- `GardenScene`：渲染分层场景、成长阶段、布置物和探索热点。
- `GardenActionDock`：提供“记录”“照料”“布置”三个主入口。
- `GardenRecordSheet`：承载现有四选项轻量记录和完整 SWEET 链接。
- `GardenCareSheet`：在当天有资格时提供三种照料选择。
- `GardenLayoutSheet`：展示已解锁位置和允许放置的预制物件。
- `GardenKeepsakeDrawer`：浏览、添加和删除日期型纪念物。
- `GardenFactsPanel`：仅展示去重参与日、历史记录入口和提醒设置。
- `gardenCatalog`：集中定义物件键、位置、解锁节点和双语显示键，客户端和服务端共享稳定标识。

手机首屏优先显示庭院。操作面板以底部抽屉出现，不跳离当前场景。桌面端允许更宽场景，但不把表单固定成长期占据一半页面的卡片列。

现有三页首次介绍改为庭院内的两步可跳过提示：先说明“记录后可以照料”，再说明“池塘、长椅和访客可以探索”。实际庭院始终在提示后方可见。

## 9. 无 AI 内容边界

- 从 `/api/garden` 响应中移除 `recentRhythm`；花园不读取 `sweet_records.summary`。
- 花园页面不请求 `pages/api/ai/` 下的任何路由。
- 纪念物由用户从固定类型中选择，不根据感受或回答自动生成。
- 文案只描述事实与可用操作，例如“今日已记录”“可以照料一次”“本月参与 6 天”。
- AI 小结仍可在原有 SWEET 记录流程中存在，但不在花园展示或复用。

## 10. 数据设计

### 10.1 继续复用的数据

- `tempo_check_ins`：只读取创建日期，现有感受值继续用于该记录自身，不进入成长判断。
- `sweet_records`：只读取创建日期；不读取回答、总结或建议。
- `tempo_reminder_preferences`：继续保存关闭、每天或每周提醒。

### 10.2 新增的最小私有状态

实施时新增三类本人私有数据：

1. 每日照料：用户、上海参与日期、照料动作键、创建时间；同一用户同一日期唯一。
2. 庭院布置：用户、固定位置键、物件键、更新时间；同一用户同一位置唯一。
3. 纪念物：用户、参与日期、纪念物类型、创建时间；同一用户同一参与日期最多一个。

这些表不保存成长分数、AI 内容、SWEET 正文、自由文本或情绪解释。成长阶段和解锁资格始终从参与事实派生，避免出现第二套可漂移的分数。

### 10.3 授权与 RLS

- 所有写操作从 bearer token 验证当前用户，并复用现有学生资格与知情确认检查。
- API 忽略客户端提交的用户 ID、角色、参与天数、阶段或解锁状态。
- 服务端校验动作键、位置键、物件键、参与日期和解锁资格。
- 新表启用 RLS，并使用 `auth.uid() = user_id` 的 `USING` 与 `WITH CHECK` 所有权条件作为纵深防护。
- 延续当前服务端 API 模式，不把 `service_role` 暴露给浏览器。
- 家长、老师、学校负责人和平台管理员不获得这些表或接口的读取能力。
- 用户可删除纪念物或更换布置；账号注销时相关行通过外键级联删除。
- 每日照料、庭院布置和纪念物进入用户本人的 Account 数据导出，但不进入任何其他角色的数据视图。

任何迁移文件、RLS、授权或正式 Supabase 应用操作都需要在实施阶段另行明确批准。本设计批准本身不授权数据库变更。

## 11. API 边界

现有 `/api/garden` 保留 GET、轻量记录 POST 和提醒 PATCH，以减小已有调用改动。GET 改为返回：

- 去重后的参与日统计。
- 主植物阶段和庭院场景等级。
- 当天是否有参与记录、是否仍可照料。
- 当前布置、已解锁位置与可选目录。
- 纪念物的日期与类型。
- 提醒偏好。

新增窄接口分别处理每日照料、固定位置布置和纪念物创建／删除。每个写接口都有独立的输入枚举、大小限制、本人速率限制和安全错误响应。数据库唯一约束保证网络重试不会产生重复照料或重复纪念物。

## 12. 失败与恢复

- 加载时先显示静态庭院轮廓，不猜测成长状态；数据成功后补齐阶段、物件和当天状态。
- 未登录返回登录入口；资格不足显示现有受限原因；真实故障显示可重试错误，三者不得混用。
- 长期状态只在服务端确认后更新。失败时保留用户刚才的选择，不播放成功动画。
- 重复提交返回已有结果或明确的幂等成功，不增加第二次成长。
- 单个装饰资源加载失败时，基础庭院、记录入口和无障碍文本仍可使用；使用同风格中性占位，不显示破图。
- 服务端 5xx 继续记录不含用户正文、邮箱、token、OTP 或私密记录内容的脱敏操作元数据。

## 13. 国际化与无障碍

- 新增键同时进入 `locales/zh-CN.json` 与 `locales/en.json`，保持结构一致。
- 内部动作键、物件键和位置键不翻译；展示标签通过字典获取。
- 所有热点都是可聚焦按钮，具有可理解的名称、顺序和可见焦点。
- 底部抽屉打开时管理焦点，关闭后把焦点返回触发按钮。
- 场景提供简洁整体替代文本；装饰性分层对辅助技术隐藏；状态变化通过非打断式 live region 宣布。
- 触控目标不小于 44×44 CSS 像素，手机页面无横向溢出。

## 14. 验证

### 14.1 单元与接口

- 上海日期转换、跨月／跨周边界和两类记录去重。
- 1、3、7、14、28 日节点和漏记不倒退。
- 四种感受获得相同成长结果。
- 未登录 401、资格不足 403、本人允许、跨用户拒绝。
- 未解锁物件、非法位置、非法动作和伪造日期被拒绝。
- 同日重复照料和纪念物创建保持幂等。
- 花园 GET 与页面代码不读取或返回 AI 小结。
- 账号注销级联清理新增私有行，其他用户数据保留。

### 14.2 页面回归

- 中文和英文首次提示、记录、照料、探索、布置、纪念物和错误状态。
- 桌面、常见手机宽度、减少动态效果、键盘和屏幕阅读器名称。
- 插画资源失败、API 失败和保存重试。
- 无横向溢出，底部抽屉不会遮挡主要操作。

### 14.3 项目检查

- `pnpm typecheck`
- `pnpm build`
- 花园专项 Playwright
- 相关权限与账号注销测试
- 数据库变更获批后运行 RLS 测试和 Supabase advisors

真实 iPhone Safari、安卓 Chrome 和微信内置浏览器仍需按试点清单保留人工验收，桌面自动化不能替代这些证据。

## 15. 推进顺序

1. 制作并审核正式插画资产和手机安全裁切，不接入运行时生成式图片。
2. 在不改数据库的前提下完成静态 `GardenScene`、动作抽屉和响应式布局。
3. 经明确批准后创建本地迁移、RLS 和私有状态接口。
4. 接入去重参与日、每日照料、布置和纪念物。
5. 完成中英文、无障碍、失败状态和自动化回归。
6. 在本地及隔离测试环境验证；正式 Supabase、正式站部署和真实账号操作分别取得明确授权。

## 16. 完成标准

用户进入花园时能立即看到一座以最初小草稿为基准的完整治愈庭院；完成当天首次参与后可选择一次照料并得到明确但克制的反馈；可自由探索、在固定位置选择预制物件、主动保存或删除无自由文本的纪念物。所有长期状态均为本人私有、服务端校验、可删除且随注销清理。花园不显示、调用或生成 AI 内容，并通过双语、权限、移动、减少动态效果和失败恢复验证。
